# 神社・御朱印投稿サービス データベース設計

## 1. テーブル設計

### 1.1 ユーザー関連

#### users（ユーザー）
| カラム名 | データ型 | 制約 | 説明 |
|---------|---------|------|------|
| id | BIGINT | PRIMARY KEY, AUTO_INCREMENT | ユーザーID |
| uid | VARCHAR(255) | UNIQUE, NOT NULL | Firebase/Auth0等の認証ID |
| email | VARCHAR(255) | UNIQUE | メールアドレス |
| display_name | VARCHAR(100) | NOT NULL | 表示名 |
| profile_image_url | TEXT | | プロフィール画像URL |
| bio | TEXT | | 自己紹介文 |
| is_active | BOOLEAN | DEFAULT TRUE | アクティブフラグ |
| created_at | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP | 作成日時 |
| updated_at | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP ON UPDATE | 更新日時 |

**インデックス**: `idx_uid (uid)`, `idx_email (email)`

#### user_auth_providers（認証プロバイダー）
| カラム名 | データ型 | 制約 | 説明 |
|---------|---------|------|------|
| id | BIGINT | PRIMARY KEY, AUTO_INCREMENT | ID |
| user_id | BIGINT | NOT NULL, FK→users.id | ユーザーID |
| provider | VARCHAR(50) | NOT NULL | プロバイダー名（google, twitter等） |
| provider_user_id | VARCHAR(255) | NOT NULL | プロバイダー側のユーザーID |
| created_at | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP | 作成日時 |

**インデックス**: `uk_provider_user (provider, provider_user_id)`, `idx_user_id (user_id)`

#### user_stats（ユーザー統計）
| カラム名 | データ型 | 制約 | 説明 |
|---------|---------|------|------|
| user_id | BIGINT | PRIMARY KEY, FK→users.id | ユーザーID |
| post_count | INT | DEFAULT 0 | 投稿数 |
| total_likes_received | INT | DEFAULT 0 | 獲得いいね総数 |
| visited_shrine_count | INT | DEFAULT 0 | 訪問神社数 |
| collected_goshuin_count | INT | DEFAULT 0 | 収集御朱印数 |
| registered_shrine_count | INT | DEFAULT 0 | 登録神社数 |
| registered_goshuin_count | INT | DEFAULT 0 | 登録御朱印数 |
| follower_count | INT | DEFAULT 0 | フォロワー数 |
| following_count | INT | DEFAULT 0 | フォロー数 |
| updated_at | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP ON UPDATE | 更新日時 |

## 3. 主要な設計ポイント

### 3.1 パフォーマンス最適化
- 統計情報は`user_stats`テーブルで非正規化して管理
- ランキングはスナップショット方式で事前計算
- 適切なインデックスによる検索・集計の高速化

### 3.2 拡張性
- ENUMの使用により、新しいランキング種別やバッジ種別の追加が容易
- 画像は別テーブル管理で、複数画像への対応が可能
- 承認フロー実装により、ユーザー投稿コンテンツの品質管理が可能

### 3.3 データ整合性
- 外部キー制約による参照整合性の確保
- カスケード削除による関連データの適切な処理
- タイムスタンプによる更新履歴の追跡
